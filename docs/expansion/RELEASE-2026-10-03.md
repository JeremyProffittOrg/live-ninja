# Main release selection - 2026-10-03

This release integrates the independently reviewed native Jobs and approval checkpoint based on f5b57a2c9970b00c509a0f59a9c5d7ce51204ef4. The full expansion roadmap remains incomplete.

Included: durable in-app reminder/review Jobs, bounded history and retries, web/native controls, default-off cloud scheduling, strict JSON validation, trusted rule writes, owner-only exact-action coding approval receipts with launch blocked, proposal review UI, honest memory deletion results, and corresponding tests/Help.

Excluded: email-dispatch replacement and its IAM/event-mapping changes, because mixed legacy/new invocation migration requires pause/drain not performed by the current workflow. The original consumer stays intact. The separate local source package retains that work. Also excluded: unverified schedule-preview code; no memory suppression, dispatch attempt ledger or artifact revision implementation landed.

Pushing main runs the existing production deployment workflow: Go vet/tests, applicable Nova image build and ECS restart, SAM deployment, static asset publication and existing configuration/log cleanup. No workflow or provider grant changes are introduced. JobsSchedulingEnabled defaults false; this release does not enable scheduled cloud jobs. New APIs and proposal-only behavior take effect after successful deployment. Android verification runs on main, while signed app publication requires separate manual dispatch; no physical tablet installation is part of this release.

Local validation of the selected tree is recorded in the task delivery receipt. Prior native evidence covers the identical Android source: 418 JVM tests and 6 isolated-emulator UI tests. Prior browser evidence covers the identical web source: 34 desktop/mobile cases and 43 JavaScript tests. These do not establish live provider integration, full accessibility certification or Android production login/backend behavior.

Before future coding launch: recoverable dispatcher, dedicated isolation and fresh execution approval. An approved_blocked receipt never becomes permission to launch later. Before scheduling: isolated DynamoDB/IAM verification, malformed-index recovery/alerting and operational limits. The legacy email consumer remains a known separate reliability limitation until its controlled migration.
